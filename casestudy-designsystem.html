01 · Overview

A design system is only real when it ships

This portfolio is the design system. Every decision — type scale, colour tokens, spacing rhythm, component architecture, accessibility rationale — is documented here as evidence of how I think about systems design, not just screen design.

The system serves nine pages: a homepage, a work index, three writing pages, and five case studies. Each page shares identical nav, footer, theme toggle, and reveal animation behaviour — without a single line of duplicated CSS. The token layer makes both dark and light mode work correctly across every component with zero mode-specific overrides in page-level CSS.

"The constraint of building a system for one product — your own portfolio — forces every decision to be justified, not assumed."

02 · Colour Tokens

A token layer that does the heavy lifting

All colour values are defined as CSS custom properties at the :root level, with a full override set on [data-theme="light"]. Every component references tokens — never raw hex values. Switching the mode attribute on <html> triggers the entire site's colour transformation with a single attribute change and a 350ms transition.

--ink #f0f0ee #1c1c1c Primary text, headings
--muted #b8b8b6 #4a4a4a Body copy, secondary labels
--indigo #b8b0ff #3730a3 Primary accent — interactive, hover, active states
--teal #7dd3cc #0f4a45 Secondary accent — case study colour identity
--border rgba(255,255,255,.08) rgba(0,0,0,.09) Dividers, card borders — must use rgba (see note)
--indigo-subtle rgba(184,176,255,.07) rgba(55,48,163,.05) Hero gradient, pullquote bg — semi-transparent by design

Why do --border and --indigo-subtle use rgba instead of hex?

These two token categories need transparency to work correctly. Borders and subtle fills must be semi-transparent so that the exact background colour showing through doesn't matter — the same token works whether it sits on --bg, --bg2, or --surface. A hex value like #2a2a2a would only look right on one specific background; rgba(255,255,255,.08) adapts to whatever sits beneath it. Solid colours like --indigo and --bg don't need this behaviour, so hex is used for clarity and precision.

Why no raw hex values in component CSS?

If a component references #b8b0ff directly, it is wrong in light mode. Tokens mean the component is mode-agnostic by default — the correct value is always provided by the cascade, not hardcoded at the component level.

03 · Typography

Three typefaces, one voice

The type system uses three families with distinct, non-overlapping roles. The contrast between them — editorial serif, geometric sans for labels, and monospaced code for body — creates hierarchy without relying on size alone. All headline sizes use clamp() to scale responsively across viewport widths.

Cormorant Garamond — display
Weight 300, italic for em elements
Used exclusively for headings and pull quotes. The contrast between its extreme lightness and high stroke contrast creates a distinctive editorial quality. Italic variants on <em> elements are coloured with the accent token — reinforcing hierarchy with colour and style simultaneously.
Syne — UI labels
Weight 700, tracked wide
Used only for section tags, nav links, card titles, and component headings. Its geometric quality reads as structured and contemporary alongside the organic serif. Never used for body copy — the optical weight contrast would collapse the hierarchy.
DM Mono — body
Monospaced body copy as a deliberate choice
Using a monospaced font for body text is unconventional. The decision reinforces the portfolio's technical identity — it signals a designer who codes — while maintaining readability at 14px/1.7 line-height. The even rhythm of monospaced type also pairs well with the high-contrast serif display font.

05 · Accessibility

Accessibility decisions that shaped every choice

Contrast — WCAG AA throughout, AAA where feasible
All body text on backgrounds meets 4.5:1 AA minimum. The indigo accent on dark background achieves 7.2:1 AAA. Token values were chosen by running the contrast formula first, then adjusting for aesthetics within the passing range.
Focus management — visible rings on all interactive elements
:focus-visible is used rather than :focus, so keyboard users get a visible ring while mouse users don't see it on click. The ring uses the accent token and a 3px offset — large enough to see, tight enough not to obscure adjacent content.
Reduced motion — all animations respect the OS preference
@media (prefers-reduced-motion: reduce) sets all animation and transition durations to 0.01ms across the entire system. Users who have this preference enabled get an immediate, no-animation experience without any JavaScript.
Semantic HTML — structure before style
Every page uses a single <h1>, with a consistent heading hierarchy. Navigation uses <nav> with aria-label. Interactive elements are <button> or <a> — never <div> with an event listener. Custom cursor has aria-hidden="true".
Alt text — every image carries a description
All meaningful images across the portfolio use descriptive alt attributes that convey content, not just label the subject. Decorative elements — background gradients, SVG line art, the custom cursor — use aria-hidden="true" or empty alt="" so screen readers skip them entirely. Image placeholders in case studies use role="img" with an aria-label that describes what the final image will show. This means the pages are navigable by screen reader even before real screenshots are added.
06 · Architecture

Nine pages, one shared language

No build tools, no preprocessors, no framework. The system is implemented in vanilla HTML, CSS, and JavaScript — a deliberate choice that prioritises performance and portability over developer convenience.

CSS custom properties as the token layer
Single source of truth for every visual decision
All spacing, colour, radius, and typography decisions flow through the token layer. Adding a new page requires copying the token block — every component then works correctly by inheritance, with no page-level overrides needed.
IntersectionObserver for reveal animations
Scroll-triggered reveals without layout thrashing
The .reveal class starts at opacity:0; transform:translateY(24px). An IntersectionObserver adds .visible when the element enters the viewport, triggering a CSS transition. No JavaScript computes element positions — the browser handles all geometry.
localStorage for theme persistence
Theme survives navigation and session reload
The theme is stored in localStorage and applied before paint by reading it in a synchronous IIFE. This prevents the flash of incorrect theme on page load. The system also checks prefers-color-scheme as the fallback for first-time visitors.
